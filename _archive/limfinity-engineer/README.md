# Limfinity 工程专家（limfinity-engineer）

南昌大学第二附属医院生物样本资源中心 Limfinity（RURO LIMS）平台工程专家，覆盖十大核心能力（含 N1 公网隧道 + 微信云函数同步 Limfinity → CloudBase、方案C 内网 .56 直连同步 Limfinity → Supabase）：

1. **外部数据源 → Limfinity 增量同步**：WPS 多维表 / 腾讯文档智能表 → Limfinity 落库（2026-08-07 跑通「WPS 多维表 → 来访人员登记表」）。
2. **Limfinity 7.0 仪表板 HTML 渲染**：纯 CSS 图表、ERB 模板铁律、老内核 CSS 兼容（flex/gap 失效对策）、背景/滚动修复、图片渲染（2026-08-13 温湿度监控平台实战，29 台设备全服务端渲染）。
3. **Limfinity 7.0 `run_script` 外部触发实时同步**：数据源在 Limfinity 外部时，由推送代理（Python + nssm 常驻）增量 POST 到 `/api/run_script`，Limfinity 侧 Helper Script（须勾「通过API调用」）落库并回写同步结果（2026-08-14 大华门禁刷脸记录 → 门禁出入记录实战跑通）。
4. **妙哒导出 Taro 质量管理系统小程序开发与 Supabase 后端**：字段纯配置补全 Limfinity 40 科目、多主题 CSS 变量体系、Taro UI/UX 美化（登录页/首页模块网格/图标对比度/横排卡片/主题即时切换）、自托管 Supabase 打通、B2 数据留院公网发布（2026-08-15~17 实战，详见 `references/miniprogram_dev_experience.md`）。
5. **Limfinity 虚拟机基础设施运维（VM Ops）**：Ubuntu 大版本升级收尾（22.04 → 24.04.4 LTS，upstart → systemd 迁移）、PostgreSQL 大版本迁移与残留集群清理、netplan 静态 IP、Limfinity VM Console 调出（tty1 自动登录 sysadmin → syscon.rb）与分辨率匹配正式机、系统清理瘦身、logrotate 修复、升级后全面体检（2026-08-17~18 实战，详见 `references/limfinity_vm_ops.md`）。
6. **微信云开发 CloudBase 后端 + 小程序账号体系与登录**（2026-08-27 实战）：Limfinity 主数据经 frp + 官方 `/api` 抽取落地 CloudBase `master_data` 集合（导入三要素踩坑：文件名须 `.json`/`.csv`、内容须 JSON Lines、格式选 JSON Lines）；小程序账号体系从「仅微信自动登录」改为「账号密码为主 + 微信备选 + 登录后绑定微信」会话模型（AuthContext 登录态、passwordLogin/bindWechat 云函数、鸡生蛋 bug 修复）；微信云开发环境坑（代理 ECONNREFUSED 7897、云函数须部署才生效、module_schema 无害降级）。完整知识见关联 Skill `limfinity-cloudbase-sync`。
7. **微信开发者工具 CLI 自动化（预览／发布／自动截图）与自定义 tabBar**（2026-08-29 实战）：探明本机 CLI 位于 `C:\Program Files (x86)\Tencent\微信web开发者工具\cli.bat`、**服务端口 48616 已开启**，可不碰 GUI 完成「打开项目 → 清缓存 → 编译 → 出真机预览二维码 → 上传代码」；并可用 `cli auto` + `miniprogram-automator` 操控模拟器页面**自动截图自查 UI 改动**；同时定位并修复了「开启 `custom:true` 后底部 tabBar 整栏透明消失」的致命坑（原生组件不继承 app 全局 `:root` CSS 变量，须把变量写进组件自身 wxss）。详见 `references/miniprogram_dev_experience.md` §10.9 / §10.11。
8. **N1 公网隧道（独立 frp + 阿里云 Caddy）与微信云函数同步（2026-08-29 实战）**：内网 Limfinity /api 经独立新建 `frpc_limfinity.toml`（不动闲鱼 `frpc1.toml`）→ 阿里云自建 frps:7000（TLS + 自签 SAN 证书）→ Caddy `limfinity.nc2h-bio.cn`（BasicAuth `sync` 闸 + Let's Encrypt）→ 微信云函数 `limfinityProxy` 落地 CloudBase `module_schema`/`master_data`；双层鉴权、wx-server-sdk `set({data})` 包裹、云函数默认 3s 超时改 60s（config.json 不生效）等全套坑已闭环（written:43）。
9. **方案C：内网 .56 直连同步 Limfinity → Supabase（单库架构，去云函数、去 N1 隧道）（2026-08-27 实战）**：`.56` 常驻 Python 脚本内网直连 `.46` `/api` 拉 43 类型字段定义 + 主数据 → 写本地 Supabase `module_schema`/`master_data`；小程序经公网 `supabase.nc2h-bio.cn`（Caddy + WireGuard → .56）只读消费；0 次公网跳数、无云函数、单库。关键认知：原 CloudBase 写入形态与前端 reader 实际错配（从未真正打通），已在对齐修正，完整经验见 `references/supabase_sync.md`。**公网读取链路（2026-08-30 打通，取代不可用的 WireGuard）**改走**现成阿里云 frp 反向隧道**：中继主机（本机 / `.55`，双通）frpc 独立实例 `frpc_supabase56.toml`（`10.103.200.56:8000` → `remotePort 8001`）→ 阿里云 frps:7000 → ECS Caddy `127.0.0.1:8001`；`.56` 全程被动，**无需给它开公网、无需申请钉钉豁免**。头号坑：**安全组不放行 8001/8088，外部端口探测恒为 CLOSED，必须端到端 HTTPS 验证**。详见 `references/supabase_sync.md` §9。**自定义字段同步（2026-08-30 打通）**：自定义字段**不是 DB 列**，`subject.attributes.keys` 永远只有内置列——这是「同步过来只有内置字段」的唯一根因；正解是**字段定义取 `SubjectType#properties`（Property 模型）、取值用 `subject.get_value(property.name)`**（与 `set_value` 同源），生产脚本 `scripts/limfinity_helper_script_v8.rb`。同时沉淀方法论：**猜不到 Limfinity API 就回传 introspection**（class / associations / columns / 样例对象 keys 一次打出），实测三轮收敛（v6、v7 各盲猜一轮全灭，v7 靠 introspection 一次锁定 `properties:has_many`）。详见 `references/supabase_sync.md` §10。完整知识见 `references/n1_frp_tunnel_cloud_fn_sync.md`；另自托管运行期排障（Envoy 取代 Kong、compose 只用 service 名、Studio 密码改后重建 api-gw、cron 覆盖手改）见 §11；另沉淀「用 nssm 把 Node 常驻程序（frpc 隧道 / sync-health-poller 轮询器）注册成 Windows 服务（开机自启、崩溃自愈）+ PowerShell 静默坑（2>&1 | Out-Null 修复 NativeCommandError、& 是调用运算符非分隔符）」见 §12；另沉淀「方案C 文件附件存 Supabase Storage 终局解耦架构（独立上传 worker 解耦主同步、FileProxy 字节读取、内网直传绕过公网 Kong、Encoding 防御、部署前链路探针）」见 §13。
