# 材料归集与完整性核查

适用：从网盘/钉盘批量下载的申报材料包 → 判"谁交了、谁没交、交的是不是空壳"→ 出核查表与报告。

## 一、目录结构（2026 年度实际形态）

```
2026年职称材料_已解压/
  正高-医师/ 副高-医师/ 副高-护理/ 副高-药技/
  副高-副系列/ 副高-自然科学/ 正高-药技/
    <姓名>/ 或 <姓名>.zip 或 <姓名> 的申请材料/
      ……
```

存在**同名嵌套中转层**：`原始材料\副高-自然科学\副高-自然科学\xxx.zip`。

## 二、人员—材料归集

- **最长姓名优先**：先按姓名长度降序，在材料条目名中命中的**最长姓名**即归属人（`陈艳慧` 优于 `陈艳`）。
- ⚠ **严禁使用 `(?![一-龥])` 边界规则**。中文姓名后常紧跟"副高申请材料""主任医师"等汉字，实测**漏配 8 人**。
- 扁平结构下直接取 `<姓名>` 文件夹名（去掉尾部 `(工号)`）。
- **同名处理**：汇总表存在重名（如"陈玉兰"2 人）。目录只有 1 个材料包时必须人工核实归属。
- **一人多包**：列为"重复提交"，须指定正式件。

## 三、目录下钻（极易踩坏）

- 下钻条件必须严格限定为**条目名 == 类别名**。
- ⚠ 若放宽为"无直接文件的目录"，会误伤大量"外层文件夹 + 内层同名解压文件夹"的个人包——实测 **8 个条目被拆坏**，人员目录被清空。
- **清理重复材料的前置校验（强制）**：判定"删除较旧件"前，必须先校验**最新件可用**（非空目录 且 非占位件）。钉盘/网盘批量下载常出现"最新件是 0 文件空目录或 536 字节占位、旧件才是真材料"，机械按时间删会**永久丢失数据**。已实测拦截 4 例（杨伟明、范纪昌、邱敏姿、魏美林）。

## 四、四类"假材料"判据

| 类型 | 判据 | 处置 |
|------|------|------|
| **网盘下载失败占位件** | zip 魔数为 `PK`，但 `getsize < 2000` 且解析失败；内容实为"今日下载流量已超限"JS 提示（典型 536 字节） | 不计为已交，列入催补 |
| **空白模板** | 文件名含 `样式\|模板\|模版\|参考\|空白\|样例`（如"业绩印证材料目录（样式）.doc""专题报告参考模版.doc"） | 标"疑似仅交空白模板" |
| **空目录** | 目录存在但 `files` 为空 | 计未提交 |
| **一人多包中的不可用件** | `files` 非空且不以 `<` 开头、不为 `<未知类型>` | **"可用优先"**：先筛出可正常展开的条目，再取文件数最多者为主条目 |

⚠ **"可用优先"是硬要求**：否则会选中钉盘/网盘占位件，把已交材料的人误判为缺件（魏美林案例）。

## 五、判定局限（必须在报告中声明）

- 只能判"**有无该文件**"，**不能**判内容是否填写、是否盖章、是否落在时间窗。
- 无语义文件名（如 `534-1141-1-SM.pdf`）无法识别其内容性质。
- 重名、嵌套、占位三类情况必须单列工作表供人工复核。

## 六、2026 年度终稿结果（229 人，基于正式目录《2026年职称申报人员电子材料》）

- 材料可核对 **225（98.3%）**｜整合式 PDF 1｜未提交 **3**｜占位 0
- 名单以目录内 `2026申报人员汇总.xlsx` 为准（已合并重复"陈玉兰"，229 人；旧表 230 人多算 1 行）
- **真正缺材料 3 人**：陈艳慧（检验科 副主任医师）、吴萍（耳鼻喉-头颈外科 副主任医师）、彭敏（感染性疾病科 副主任技师）
- 周亮（7z）后已解压，纳入有效
- **李俐华归类错位**：主任医师的材料曾两轮被放进"副高-医师"目录 → 须按"**目录实归人数**"而非"目录条目数"判断缺口

## 七、整合式 PDF 的处置口径（人事处）

- 文件对封装形式**无明文** → **单个 PDF 不单独构成退回事由，可受理**；但须实证扫描其内容，区分"形式问题"与"实质缺件"。
- **5 份病案分析报告 + 附件6 工作情况表为门槛必备，缺即不予通过**。
- 《代表作送审表》对**已取得相应资格者可免**（五审三中仅适用未取得资格者）。
- 处置：**限期 5 个工作日补正，保留批次序号**。

## 九、Windows 删除踩坑

- `send2trash` 会把中文路径转 8.3 短名并抛异常，但**实际已删除** → 须复查目标是否消失，**不能只看返回值**。
- PowerShell `Add-Type` 被安全策略拦截；Bash 中 `$RECYCLE.BIN` 会被当作变量展开 → 须用 `chr(36)` 构造路径或写入 .py 执行。
- 回收站 `$I` 元数据格式：版本@0(4B)、大小@8(8B)、删除时间@16(8B)、**路径字符数@24(4B)**、Unicode 路径@28（**非固定 520 字节**）。校验脚本 `_verify_recycle.py`。
