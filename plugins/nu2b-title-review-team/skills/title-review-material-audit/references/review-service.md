# 查询服务与工程铁律

## 一、服务

- **启动**：`cd $R && python _serve_query.py 8765`
  - ⚠ Git Bash 里 `nohup ... &` 起的进程会随 shell 退出被杀 → 必须用后台任务方式启动
  - ⚠ **改完 Python 必须 kill 旧进程再重启**，否则旧代码仍在跑（`netstat -ano | grep ":8765"` 取 PID，`taskkill //F //PID <pid>`）
- 单文件、零依赖（`http.server`），前端 JS 内嵌在 `r'''...'''` 模板里

### 主要路由

| 路由 | 用途 |
|------|------|
| `/` | 主查询台（229 人，28 列） |
| `/p/<工号>` | 人员详情独立页（与抽屉共用 `renderPersonHTML`，**单一数据源**） |
| `/pdf/<doc_id>` | 原件预览页（Range 流式） |
| `/sp/<sp_id>` | 拆分件直连 |
| `/api/pdf/<doc_id>` | 206 / 416 流式二进制 |
| `/api/ocr/<doc_id>`、`/api/links` | OCR 文本、槽位映射 |
| `/api/person/<pk>` | 人员全量 JSON |
| `/api/open-folder/<工号>` | 本机弹资源管理器打开该人材料目录 |

## 三、科技处审核机制

- **唯一核对入口 `/pdf/<doc_id>`**；人员页「人事汇总后业绩」是汇总/回改入口。**保存一律 merge**（`rev_save()` 缺省保持原值）
- **三类口径分开**：
  - 论文 → 第一作者｜共同第一首位｜共同第一非首位(不合规)｜通讯｜共同通讯末位｜共同通讯非末位(不合规)｜既非第一也非通讯｜存疑需举证
  - 课题 → 负责人｜参与前五｜第六及以后
  - 专题报告 → 内容属实｜名称一致｜不予认定
- **自动"通过"充分条件**：核心代表作全部命中身份确认项；专利/专著/课题/奖励未核对**不阻塞**。`manual` 优先
- **合并件槽位（38 人）**：`?slot=` **优先于**对接表反查（否则点论文2 进去显示的还是论文1）
- **四分法**：A 建议拆 11 人 → 29 件已执行；B 缺件催补 15 人；C 存疑待人工 6 人；D 无文本层 6 人
- 列表页「科技处审核」是首列；⚠ `persons()` 被 `min(200, …)` 卡死，**导出走 `persons(params, cap=5000)`**

### 附加确认项与审核意见自动总结（2026-10-19）

**② 附加确认全集**（`EXTRA_OPTS`，与前端 `REV_EXTRA` 必须一致）：
`第一完成单位为本院`｜**`本院非第一完成单位`**｜`原件内容与申报名称一致`｜`已见复制比检测报告（≤30%）`｜`不予认定`

- 两个"第一完成单位"项**互斥**（勾一个自动取消另一个），JS 用事件委托绑 `#g2, .revbox`，两处页面都生效
- `本院非第一完成单位` 必须同时进 **`NEG_OPTS`**（后端状态机）与 **`REV_NEG`**（前端标红），否则勾了状态仍显示通过
- 课题分支（`_cands`）也要给这两个项——课题的"立项单位须为本院"同理

**⑤ 审核意见：单条页写单条，汇总在个人详情页**（用户口径 2026-10-19）

> **不能因为是同一个人，一篇代表作有问题就把同一意见套到另一篇。**
> 单条审核页的 ⑤ **只写当前这一条**；整人跨条的汇总放到个人详情页独立栏目。

**单条审核页（`/pdf/<doc_id>`、`/sp/<sp_id>`、`/nd/<工号>?slot=`）**
- ⑤ 标题写明「**仅本条**」，初值 = `opinions[slot]`（人工已写）→ 否则 `_opinion_one()` 自动生成
- 保存写 **`opinions{slot: txt}`**，**绝不写整人 `note`**（否则后一条覆盖前一条）
- 前端只用 `buildRevOpinion()`（`buildAllOpinions()` 已删除）；`data-auto=1` 时勾选变化自动同步
- 要素顺序：**署名事实 → 身份结论（含与自填是否一致）→ 附加确认 → 第一完成单位结论 → 结论**
- ⚠ **无原件条目**走 `NO_DOC_OPTS` 三选项，不在 `IDENT_OPTS` 里。取 `ident` 时必须回落
  `NO_DOC_OPTS`，否则 `ident` 恒为空 → 结论恒为"建议通过"（实测踩到）。
  且无原件时**不写**"核对作者身份…"这句，结论按选项分：待补交→待补材料 / 政策可免→通过 / 不予认定→不予认定
- ⚠ **`elif` 链 fall-through 坑**：② 已勾「第一完成单位为本院」时跳过 ④ 的重复句，
  此时「未识别」分支必须显式限定 `fu_v is None`（前端 `d.fu === 'n'`）

**个人详情页「科技处审核意见汇总」**
- 位置：紧跟「人事汇总后业绩」之后；**替换掉原「电子版未见」栏目**（该栏已移除）
- 后端：`person_detail()` 输出 `审核意见汇总 / 审核意见条数 / 审核意见人工条数 / 审核意见未核对`
  （由 `_opinion_bundle(pk)` 生成：人工 `opinions` 优先，缺失才自动生成）
- 排序用 `slot_order()`：⚠ 不能直接字符串排序，`其他代表作10` 会排到 `其他代表作2` 前面
- 展示：逐条编号卡片，`.opinbody.opneg` 红（不予认定）、`.oppos` 绿（建议通过）；底部列"尚未核对"；右上「⧉ 复制」
**列表页（人员查询界面）**
- 新增 `REV_NOTE_COL = '科技处审核意见汇总'`，`OUT_COLS = [REV_COL, REV_NOTE_COL] + FORM_COLS`，紧跟状态列
- ⚠ **该列 330px，不能进冻结区**：前端冻结判定已从"前 NF 列"改成**列集合**
  `FRZ = {__sel__, 序号, 科技处审核, 科室, 姓名, 工号}`，left 偏移只对冻结列累加。
  若沿用"前 N 列"，插入新列后会把 330px 也冻进去，挤压可视区。
- 单元格只显示前 2 条（每条截 40 字）+「…共 N 条」，完整内容放 `title`，**点击复制全文**（不跳人员页）
- 性能：`persons()` 里只有 `rev_row(pk)` 非空（已有审核记录）的人才算 `person_opinion_text()`，未审核者置空

**导出 Excel**
- 列顺序：**序号 | 科技处审核 | 科技处审核意见汇总 | 科技处审核勾选摘要 | 27 人事列**
  ⚠ 科技处三列必须**紧跟状态列**，不能像其他附加列那样追加到末尾
  （用户口径 2026-10-19「导出的意见汇总也跟在科技处审核后面一列，不要放在最后」）。
  实现：`columns = [REV_COL] + [REV_NOTE_COL] + ['科技处审核勾选摘要'] + cols`，`meta_cols` 留空。
- 意见汇总列取 `person_opinion_text(pk, checks, note)`——**与列表页、详情页同源**
  （人工逐条 → 有勾选时自动生成 → 旧的人级 note）。⚠ 不能只拼 `opinions`，
  否则未手写过意见的人导出来全是空。
- 列名统一为 `REV_NOTE_COL = '科技处审核意见汇总'`（与列表页一致）；列宽 62、
  `wrap_text=True`、按内容估算行高（每行约 30 字，上限 260）
- 导出面板选项文案改为「审核意见汇总（逐条编号）」

**⚠ 空覆盖防御**：`rev_save()` 末尾加保护——已有记录却把 `slots` 与 `opinions` 同时清空、
且未声明 `replace: true` 时**拒绝写入**并返回 error。起因：2026-10-19 实测有一次某人的
4 条勾选被整体清空（只能凭记忆复原）。正常前端每次只提交当前一条，不会触发。

### 审核页顶部基础信息必须含「业绩起算时间」（用户口径 2026-10-19）

三张单条审核页——`/pdf/<doc_id>`（原文核对）、`/sp/<sp_id>`（拆分件核对）、`/nd/<工号>?slot=`（无原件结论）——的 `.meta` 基础信息区都要显示：

| 字段 | 来源 | 说明 |
|------|------|------|
| **业绩起算时间** | `hr_form_summary."业绩起算时间"` | **红字加粗**。审核单篇代表作时必须同屏可见，否则无法判断该篇是否落在时间窗内 |
| 申报类别 | 同上 | 正高/副高、评聘结合/申请聘任，决定适用哪套评分标准 |

- 取数统一走 `form_base(pk)`（按 `工号` 查 `hr_form_summary`），不要在各页各写一份 SQL
- ⚠ 业绩时间窗口径：资历、业绩、学历一律算到**评审上一年 12 月 31 日**；实践能力考试成绩 3 年有效

### 专题报告的特殊处理（用户口径 2026-10-18）

- **不做核对**：`_is_sr()` 命中时不渲染核对卡
- **审核页不要求"对接业绩条目"**：`slot` 为空且属专题报告时置伪槽位 `SR_SLOT`，顶部统一显示"专题报告"，只给预览/下载
- ⚠ 判据**不能只看文件名**：磁盘索引的专题报告常叫 `附件7黄文舟.pdf`，真正标记在 `pdf_doc.src = "专题报告(磁盘)"`
- 必须同时抑制 `match_score <= 0.5` 的"类型与文件性质不符"警告和 `_slotbar` 合并件条，否则专题报告页仍会喊"请选择它对应的业绩条目"
- 三级回落找原件：`pdf_doc` → 扁平目录文件名含"专题报告" → threshold 描述标题与文件名 LCS ≥ 8

### 无原件条目也可下结论

- 750 条三问中 **336 条无原件**（论文 71、课题 195、专利 32）
- 三选项（**字面量勿改**）：
  - `未提交原件，已通知本人补交` → 待补
  - `无需原件（已取得资格/政策可免）` → 计入通过
  - `原件缺失，不予认定` → 不通过
- 路由 `GET /nd/<工号>?slot=`；产出 `_论文缺原件催补名单.csv`（44 人）、`_scan_nodoc.py`

## 四、工程铁律（改前端必读）

1. **前端改动强制双检**：① 抽 `<script>` 做 `node --check`；② stub DOM 回放真实 API，`vm.runInContext` **真跑**。
   > **只做字符串 `includes` 检查 = 没验证**（脚本报错时整块不执行，页面依旧 200）。
   复用 `_js_check.py`（`JS_DUMP=1` 可导出）。Git Bash 传 `/p/xxx` 须 `MSYS_NO_PATHCONV=1`。
   ⚠ **`SCRIPT_RE` 必须排除 `type="application/json"` 的数据块**（如 `#revdata`）：否则 JSON 被当 JS 抽去做语法检查，报 `Unexpected token ':'`，误判成页面脚本坏了。
2. `_js_check.py` 抓 127.0.0.1 会被本机代理（127.0.0.1:51269）拦成 502 → 已内置 `ProxyHandler({})` + `quote()`
3. **改造函数务必整段替换**；同函数新增 `const` 前先 grep 同名声明
4. 改 `%` 格式化要重数占位符；嵌套三元改 if/else
5. ⚠ **`PERSON_JS` 原始字符串必须独立闭合**：曾因 `PAGE = r'''` 处的 `'''` 被误当闭合，导致 `renderPersonHTML` 从未注入、抽屉走过时内联渲染。修法：在 `renderPersonHTML` 结尾补独立 `'''`，并在 `_html()` 用 `PAGE.replace('</script>', PERSON_JS + '\n</script>', 1)` 注入
6. **新增材料目录必须同步加入 `DOC_ROOTS`**（文件读取白名单），否则 `safe_abs()` 返回 None → 预览全部 404
7. 申报表类数据**不是实时读文件夹**，而是已解析入库；判"附件在哪"要查 `pdf_doc.abs_path`，不要想当然
8. 核对姓名务必查库（曾把截图上的"朱菱"误读成"朱姜"并当成 Bug 排查，实为同一人工号 07061）
9. 基本信息高亮 4 项：申报类别 / 业绩起算时间 / 申报专业技术职务 / 是否选择论文

## 五、数据 sanitize

- PDF 原件带"易云"水印，正文提取需先正则清洗（噪声行为重复数字 / 云 / 易）
- 扫描附表页需 **200 DPI 渲染 + 顺时针旋转为横向**再识别
- 涉及具体分值/例数以院发文件原件为准（OCR 存在个别偏差风险）
