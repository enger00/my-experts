# 新批次受理作业 SOP（审核方视角）

> **与 `title-review-policy/references/review-workflow.md` 的区别**：那份是**申报人视角 / 医院程序视角**（六阶段八关口，回答"评聘怎么走"）；本文件是**审核方视角**（回答"人事处丢给我一批材料，我怎么干完并交付"）。
>
> 适用：新一年度（或新一批）职称评聘材料受理与审查。2026 年度 229 人即按此流程执行。

---

## 〇、四条总原则

1. **先事实，后判断**
   先把材料事实核清楚（谁交了、原件在哪、是否与他人共用），再让部门专家做政策判断。**严禁在缺件状态下让专家空判**——事实层没做完就进评分，结论必然返工。
2. **事实层主理人自办，判断层必须建团队**
   P0–P4 属事实层，走 Workflow D（主理人加载手册执行，**不启动 12 人团队**）；P5 属判断层，必须 TeamCreate 起 Workflow A/B。
3. **只出清单，不自动改**
   凡可能改变他人材料归属或认定的判定（串档改指、共用角标、缺件认定），默认 dry-run 出 CSV，经人工确认后再 `--apply`。
4. **遇异常立即暂停并说明**
   名单对不上、目录错位、占位件成批、脚本报错——停止推进，向用户书面说明现象、影响范围与建议，不自行猜测放行。

---

## 一、启动前必须向用户确认的六件事（不满足不开工）

| # | 确认项 | 为什么 |
|---|--------|--------|
| 1 | **批次年度与评聘系列范围**（正高/副高、医师/护理/药技/副系列/自科） | 决定权重口径与门槛条款 |
| 2 | **权威名单文件**（如 `2026申报人员汇总.xlsx`）与**名单人数** | 名单是唯一基准；目录条目数不可信 |
| 3 | **材料根目录**（网盘/钉盘下载后的解压目录） | 决定 `DOC_ROOTS` 白名单与后续所有路径 |
| 4 | **本次交付边界**：只做材料核查？还是要评分模拟？要不要出补正通知？ | 决定做到 P4 还是走完 P6 |
| 5 | **是否有特殊通道人员**（破格、绿色通道、直通车、抗疫一线、派遣外出/科技特派员） | 这几类口径特殊，必须单列 |
| 6 | **交付形式与时限**（公文 docx / 核查表 xlsx / 查询台页面 / 全部） | 决定最后一段投入 |

> 确认后请用户明确授权再执行。参考工时：229 人走完 P0–P4 约 1.5 个工作日；含 P5–P6 约 3–4 个工作日（视补正轮次）。

## 二、角色分工矩阵

| 阶段 | 性质 | 执行者 | 是否需要建团队 |
|------|------|--------|---------------|
| P0 受理建档 | 事实 | 主理人（沈度衡）自办 | ❌ |
| P1 归集与完整性核查 | 事实 | 主理人 + 任适之（人事处口径） | ❌（可单派任适之） |
| P2 电子化与转码 | 事实 | 主理人自办 | ❌ |
| P3 业绩条目与原件对接 | 事实 | 主理人 + 柯研深（科技类业绩） | ❌（可单派柯研深） |
| P4 合规筛查 | 事实＋初判 | 主理人自办；存疑项交柯研深 / 严守正 | ❌（结论只提示不判错） |
| **P5 分口审查与评分** | **判断** | **12 部门全体** | ✅ **必须 TeamCreate** |
| P6 汇编交付 | 汇编 | 主理人 | ❌（汇总成员结论） |

⚠ **交叉铁律**：P5 任何部门专家提出的"政策判断"若反过来要求补材料（如"这篇论文需检索证明"），必须回流到 P3/P4 补登记，由主理人统一发补正，不得由单个成员直接联系申报人。

## 三、七个阶段

### P0｜受理建档

**输入**：名单文件 + 材料根目录

- [ ] 以**名单文件**为唯一人员基准，核对人数（注意：旧版汇总表可能多算行；2026 年旧表 230 人、正式表 229 人，差 1 行重复"陈玉兰"）
- [ ] 核对**重名**（同姓名不同工号）与**名单外人员**（目录有、名单无）
- [ ] 建立批次工作区：备份主库（`.bak_<批次><时间戳>`），登记批次编号
- [ ] 确认材料根目录已加入 `DOC_ROOTS`（否则后续预览全 404）

**产出**：批次登记表（人数、系列分布、重名清单、名单外清单）
** Gate G0**：人数、重名、目录三项对齐 → 放行 P1。对不上**暂停**并报用户。

---

### P1｜材料归集与完整性核查

**输入**：解压后的材料目录

- [ ] 解压 / 拆包，识别占位件（536 字节 zip、内容"下载流量已超限"）→ 不计为已交
- [ ] **最长姓名优先**归集材料到人（禁用 `(?![一-龥])` 边界）
- [ ] 扁平化为 `原件材料/<类别>/<姓名>/<文件>`（人名目录下不嵌套）
- [ ] 判四类"假材料"：占位件 / 空白模板 / 空目录 / 一人多包中的不可用件（**"可用优先"**）
- [ ] 类别错位核查：按"**目录实归人数**"而非"目录条目数"判断缺口（李俐华案例：正高材料被放进副高目录）

**产出**：完整性核查表（总览 / 缺失统计 / 全员明细 / 重点催补 / 名单外与重复）+ 核查报告（公文格式）
** Gate G1**：可核对率 ≥ 95%；缺件名单已确认 → 放行 P2。
**必读**：`material-intake.md`

---

### P2｜电子化与转码

- [ ] Word/Excel → PDF 转码（**LibreOffice headless**，先换 ASCII 名再批量转）
- [ ] 扫描件标记（无文本层），提示人工打开，**不能断言缺件**
- [ ] 索引入库：`pdf_doc` / `pdf_link`，`doc_id` **必须字符串化**
- [ ] 专题报告专项：三级回落找原件（`pdf_doc` → 文件名含"专题报告" → 标题 LCS ≥ 8）

**产出**：可预览率统计、无文本层清单、专题报告到位清单
** Gate G2**：专题报告可预览率 ≥ 90%（**专题报告是业绩成果第 1 项、门槛必备，缺即不予通过**）；转码件已接入 `DOC_ROOTS` → 放行 P3。
**必读**：`pdf-pipeline.md`

---

### P3｜业绩条目与原件对接（三问核对）

- [ ] 申报表业绩条目 ↔ 原件逐条对接（`pdf_link` 槽位最权威；⚠ `papers.是否代表作` 自填列不可信）
- [ ] 按**正文**识别论文（前两页 4-gram 覆盖，阈值 0.72 / 中文 0.60），不信文件名
- [ ] 作者/单位/刊名解析：第一作者、通讯作者、**是否本院**（LOCAL_KW 唯一口径）
- [ ] 专题报告：不做核对，只给预览
- [ ] 门槛必备件核查：5 份病案分析报告 + 附件6 工作情况表

**产出**：三问审查结果表、缺原件催补名单（三选项字面量勿改）、科技处核对台
** Gate G3**：正式代表作对接率 ≥ 85%；缺原件已发催补 → 放行 P4。
**必读**：`pdf-pipeline.md`、`paper-meta-parsing.md`

---

### P4｜合规筛查（只提示，不判错）

- [ ] **跨申报人共用同一成果**（论文/课题/奖励）→ 紫标写姓名 + 汇总条。多为正常合作，**只提示不判错**
- [ ] **同一人同成果占多个槽位** → 占名额凑数，出清单交人事处定夺
- [ ] **串档**（多槽位共用同一 doc_id）→ 工具链分档，疑似错配只出清单，人工确认后 `--apply`
- [ ] 时间窗、复制比、负面清单线索（负面清单结论须交严守正）
- [ ] 特殊通道人员单列（派遣外出、科技特派员、破格、抗疫一线）

**产出**：`_跨申报人共用成果清单.csv`、`_同人重复申报清单.csv`、`_串档待核清单.csv`、存疑清单
** Gate G4**：三类清单均经人工确认（未确认不得进入评分）→ 放行 P5。
**必读**：`shared-achievement.md`

---

### P5｜分口审查与评分模拟（**必须建团队**）

**触发**：Gate G4 通过后，主理人 **TeamCreate**，按 Workflow A Phase 2 编排：

- 卫生系列（医/药/技）：医务处 + 病案科 + 行风办 + 门诊部 + 院感处（药学加药学部）+ 教务处 + 科技处；有临床试验/IIT 加临床试验研究中心
- 护理：护理部 + 病案科 + 行风办 + 院感处 + 教务处 + 科技处
- 自科：科技处 + 临床试验研究中心 + 教务处
- 副系列：按综合条件 80% + 科研 15% + 任职 5% 编排

- [ ] 各口按权重评分；分值以 `title-review-policy` 原文为准
- [ ] 成员结论回传主理人，**不得互相直连**
- [ ] 主理人汇编《预审报告》/《审查意见书》

** Gate G5**：各口结论齐备、异议处理完毕 → 放行 P6。

---

### P6｜汇编交付

- [ ] 《材料完整性核查报告》（公文格式）
- [ ] 《科技类业绩补正名单》/《补正通知》：**限期 5 个工作日补正、保留批次序号**
- [ ] 《代表作审查意见（科技处）》
- [ ] 公示底稿（资格审查通过名单 + 业绩公展）
- [ ] 查询台交付：勾选导出、原件预览、共用角标

**交付四件套**：①结论（是否建议受理/材料是否齐备）②分口结论 ③评分模拟表 ④风险与补正清单（**列明对应文件条款**）

## 五、最小可用路径（时间紧时的裁剪版）

若只求"这批人材料齐不齐、能不能往下走"：

```
P0（名单对齐） → P1（归集判缺） → P2（仅专题报告转码） → P4（仅跨人共用） → 出核查报告 + 催补名单
```

跳过 P3 全文对接与 P5 评分。**但 Gate G0/G1 不可跳过**——名单没对齐就判缺件，结论全废。

| 阶段 | 最致命的坑 | 手册 |
|------|-----------|------|
| P0 | 用目录条目数当人数；旧汇总表多算行 | material-intake.md |

| P4 | 用名称精确相等判共用 → 熊鸣/孙万磊漏配；专题报告未排除 → 全员互相命中 | shared-achievement.md |
| P5 | 全量重跑 `_paper_meta.py` → `INSERT OR REPLACE` 清空整列；`affi?l?i?ated` 少变体 → 131 行真本院判外院 | paper-meta-parsing.md |
| P6 | 未声明判定局限；共用清单未注明"多为正常合作" | material-intake.md |

## 七、判定局限（所有交付物必须声明）

- 只能判"**有无该文件**"，**不能**判内容是否填写、是否盖章、是否落在时间窗
- 无语义文件名（如 `534-1141-1-SM.pdf`）无法识别性质
- 重名、嵌套、占位三类必须单列供人工复核
- 共用/重复**只提示不判错**，是否构成重复申报由人事处/科技处定夺
- 评分模拟仅作预审参考，**不构成对医院正式评审结果的承诺**
