# 文献全文获取团（Lit Fulltext Team）

把「一批题录」变成「一批落盘并入库的 PDF」——先判来源走对应通道，再分片、节流、核验、对账。

## 类型

Team 型（多角色协作团队），1 位主理人 + 7 位专员。

## 功能

| 阶段 | 负责成员 | 产出 |
|---|---|---|
| **开工前交接**（Phase 0） | 戚全得（主理人） | **交接清单**：库数字 / 上次停机原因 / 起手参数卡 / 配额闸门 ⇒ **不做无用功** |
| 发现与口径 | 查新月 | 月度增量 / 缺口池快照、来源路由分派表 |
| 万方通道 | 万得通 | 万方批次下载结果 |
| 知网通道 | 甄知源 | 知网分片结果、风控与熔断处置 |
| 中华医学期刊 | 华仲明 | CMA 系列刊全文 |
| 英文出版社 | 欧思捷 | Springer / IEEE / SD 直取结果 |
| OA 与受限通道 | 康开源 | OA/PMC 结果 + **机构加白名单协调清单** |
| 质检结算 | 严守平 | 四分类 A/B/C/D 对账、账实相符核验 |

核心能力：**单会话串行编排**（Chrome CDP `:9223` 与 WebVPN 均为单会话，多通道同时跑会互相踢）、
**分片执行**（长跑会被宿主回收，必须切到单次调用内跑完）、**风控节流**（知网冷却、万方 0x05189、ScienceDirect 限流）、
**去重对账**（统计必带 `dup_of` 闸门，杜绝虚高）。

## 使用示例

- 帮我抓取上个月新增的文献，按来源分派到万方/知网/PMC 各通道把全文下载下来
- 盘点当前缺口池，按通道给我一份可执行的下载计划与预期产出
- 检查各通道健康度（CDP 会话、WebVPN、风控、限流）并汇报昨天各通道成功率
- **接着上次继续跑**（先说清上次为什么停、起手参数是多少，再开跑）

## 技能

`skills/lit-fulltext-flow/` —— **开工前交接清单**、通道登记表、路由判据与题名清洗、四分类结算口径。

> ⭐ **每次开工的顺序**：先读 `references/preflight-checklist.md`（Phase 0，5 分钟），
> 再按 Phase 1→4 走。**上次推导过、探测过、踩过的结论都在这份清单里 —— 别重来一遍。**
