# 回归用例 · Limfinity 工程专家团

版本：1.1.0 ｜ 建立日期：2026-09-07 ｜ 维护：易云

用途：验证专家团协作链路（主理人调度 → 成员产出 → 回传汇编）与单点能力均未漂移。
团队型回归除业务结果外，还需验收协作规范执行情况。

---

## R1 · WPS 多维表 → Limfinity 来访人员登记表

- **触发输入**：帮我把 WPS 多维表对接到 Limfinity 来访人员登记表
- **预期路由**：主理人 → 集成与数据工程师（limfinity-integration-engineer）
- **协作验收**：
  1. 主理人先执行 TeamCreate，再 spawn 成员
  2. 成员通过 SendMessage 回传，主理人不代写成员产出
  3. 跨成员信息流经主理人中转
- **业务预期产出**：同步脚本 + 字段映射表 + 首轮核对结果
- **判定**：□ 通过　□ 不通过

## R2 · 主数据同步至 .56 Supabase 并公网可读

- **触发输入**：怎么把 Limfinity 字段/主数据同步到 .56 本地 Supabase（方案 C）并公网可读？
- **预期路由**：主理人 → 云后端与同步工程师（limfinity-cloud-backend-engineer），必要时拉入运维工程师
- **协作验收**：多成员参与时按 Phase 串行/并行调度，前一阶段结论完整传入下一阶段
- **业务预期产出**：同步方案 + 公网读路径（Caddy / frp）+ 验证命令
- **判定**：□ 通过　□ 不通过

## R3 · 小程序构建与真机预览

- **触发输入**：改完小程序代码帮我构建并生成真机预览二维码
- **预期路由**：主理人 → 小程序工程师（limfinity-miniprogram-engineer）
- **协作验收**：构建失败时不由主理人自行改码，须回传成员定位
- **业务预期产出**：构建产物 + 预览二维码 + 构建异常处理说明
- **判定**：□ 通过　□ 不通过

## R4 · 合规与交付（新增成员：付规达）

- **触发输入**：核查 Limfinity 来访人员登记表配置是否满足 ISO 20387 记录留存与审计追溯要求，出具对照表
- **预期路由**：主理人 → `limfinity-compliance-delivery`（Workflow E）
- **业务预期产出**：条款/要求 → 系统现状 → 判定 → 整改建议 的逐条对照表，必要时附正式文档
- **验收标准**：
  1. 条款号真实可查，无编造；不确定处标注"需人工核对"
  2. 未把 ISO 13485 条款套用到 ISO 20387（仅可参考文档组织方法）
  3. 涉及体系文件**内容**时明确转交「20387 体系文档专家」，未越界代写
  4. 公文格式符合规范（A4 普通边距、方正小标宋简体标题、仿宋_GB2312 正文、行距 28 磅、页码）
- **判定**：□ 通过　□ 不通过

## 依赖技能可用性验收

重跑 `skill-asset-audit` 的 `scan_skills.py` 更新技能索引，再重跑
`gen_team_dependencies.py limfinity-engineering-team`，比对 `skill_dependencies.json`
中的依赖技能是否仍然存在。任一依赖技能消失即视为不通过，需更新对应成员 MD。

## 上下文预算验收（每次回归必查）

1. 每个 Phase 只加载本阶段所需技能，未出现全量技能罗列
2. 成员 maxTurns 未超出配置上限
3. 主理人汇编阶段未重复展开成员原始产出全文

---

## 回归执行要求

1. 成员提示词、SOP 或技能绑定变更后，回归 R1—R4
2. 协作规范任一项不通过，即判定该轮整体不通过
3. 结果留档，保留最近 5 次
